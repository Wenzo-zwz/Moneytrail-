# Moneytrail · 慢慢记账

面向 iPhone 的个人消费账本：从银行短信和支付平台账单整理记录，查看每月花了多少、花在哪，以及还剩多少预算。界面适配手机，可作为 PWA 添加到主屏幕。

界面采用石墨黑、碳纤维编织纹理与铂金色数字，手机导航、表单、弹窗和主屏幕图标使用同一套深色设计。

支持独立账号与云端同步：邮箱注册、登录、密码重置、按账号隔离的账本，以及经确认后迁移旧本机账目。需要先配置自己的 Supabase 项目；未配置时保留本机模式，不会伪装成已登录的账户。首次打开为空账本，不会把演示消费混入真实记录。

接入步骤、数据库迁移和真实账号验证见 [独立账号部署说明](docs/cloud-accounts.md)。站点地址为 <https://wenzo-zwz.github.io/Moneytrail-/>。账号版首次发布用于注册和同步测试；迁移真实账目前应先验证邮箱、换设备读取与账户隔离。

项目所有者可绑定唯一管理员，在后台查看用户目录与同步概览。设置方式和权限范围见 [管理员后台说明](docs/admin.md)。

账号版支持通过 iPhone 快捷指令接入工商银行支出短信：支持商户内嵌括号、受限门店右括号修复、金额/余额千位逗号，以及用途分类。餐饮与娱乐合并为“本地生活”，保留外卖、餐饮、按摩足疗、剧本杀密室等细类；只有美团平台名称时默认本地生活、细类未明。京东、淘宝等默认购物，明确药品、住宿、交通、教材等用途优先。群收款、其他纯支付渠道和用途不明的个人转账继续待确认。新入账短信在账本内长期保存脱敏凭据，隐藏尾号和余额；历史已删除原文不伪造恢复。JSON/CSV可保存细类、平台和凭据；支持细类统计、搜索和编辑。已有用途分类版升级时，执行 `20261025115635_local_life_receipts.sql`；手机自动化无需重新配置，详见 [iPhone 短信自动化说明](docs/sms-automation.md)。

## 开发与验证

使用 Node.js 24（见 `.nvmrc`）和 npm。在已有检出目录工作；每个云任务已隔离，无需额外创建 Git worktree。

```sh
cd /workspace/Moneytrail-
npm ci
npm test
npm run typecheck
npm run build
npm run dev -- --host 0.0.0.0
```

开发服务器使用端口 `5173`。预览生产构建：

```sh
npm run build
npm run preview -- --host 0.0.0.0
```

生产预览使用端口 `4173`。技术栈为 React 19、TypeScript 5.9、Vite 8、Vitest，PWA 由 `vite-plugin-pwa` 生成。`npm test` 覆盖金额、解析、备份、账户缓存、同步冲突和真实 PostgreSQL 权限规则；PGlite 的身份夹具不能验证托管 Supabase 的 JWT 验签或邮件服务。

浏览器冒烟测试需要 Chromium，可验证录入、导入、恢复、移动布局和离线流程：

```sh
# 首次在没有浏览器的机器上执行
npm exec playwright install chromium
npm run build && npm run test:e2e
```

本云环境已有系统 Chromium，可使用 `MONEYTRAIL_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`；默认使用 Playwright 配套浏览器。测试自行启动并清理端口 `4183` 的生产预览，不需要提前启动服务。浏览器测试受机器的浏览器能力限制，不替代必需的单元测试。

本机模式的冒烟测试需使用未注入 Supabase 配置的构建。账号和短信界面的测试使用真实 SDK 和拦截的服务夹具，命令分别为 `npm run test:accounts` 和 `npm run test:sms`；新增分类与批量流程使用 `npm run test:classification`。它们验证浏览器流程，不表示已经接通真实云端服务或完成 iPhone 短信投递实测。

`npm run test:update` 同样需要根路径、本机模式的生产构建。它在临时副本中验证真实 Service Worker 更新等待、取消更新、确认重开和其他标签页的草稿保护，不改动原构建或清除账目。

## 首版流程

1. **录入与核对**：粘贴银行消费短信，解析成待确认记录；也可以手动录入。缺少日期或商户时会提示核对，确认后才保存。
2. **账单补全**：导入微信、支付宝或通用 CSV，预览记录、修改分类，再确认保存。不同平台导出格式会变化，无法识别的行会报告，不能把导入成功视为账单已经完整。
3. **处理重复**：相同来源、交易类型和交易编号的重复导入可以识别，退款与原消费即使共享编号也分别保留；金额、类型和时间接近的记录只提示疑似重复，由用户核对。同一笔美团消费即使同时出现在微信账单和银行短信中，也只应记一次。
4. **查看本月**：查看支出、退款、分类和预算；月预算为各月共用的固定额度。账单核对状态由用户手动标记，不代表应用读取过全部支付渠道；相关月份的账目被修改后，需要重新核对。
5. **备份**：导出 JSON 完整备份或 CSV 账目。恢复 JSON 前校验格式，并在确认后原子替换当前账本，不先删除原数据；清空本地数据也需要确认。

金额以整数“分”保存，首版仅支持人民币。消费按交易日期计入对应月份；退款在收到退款的月份抵减支出。因此净支出为“支出减退款”，可能出现负数。转账、余额充值和信用卡还款应作为资金流转记录，不重复计入消费；信用卡购买本身计入消费。无法确定的记录应先核对。

## CSV 文件

支持 UTF-8 和 GB18030 文本 CSV。首版不读取 Excel 工作簿或加密 ZIP，需先通过支付平台取得可读取的 CSV 文件。账单中的非人民币消费不能直接按人民币金额导入。

通用模板：

```csv
日期,类型,金额,商户,分类,备注,交易编号
2026-10-01 12:30,支出,28.50,示例餐厅,餐饮,午餐,example-001
2026-10-02 09:00,退款,10.00,示例商店,购物,部分退款,example-002
```

类型为 `支出`、`退款`、`转账` 或 `收入`；金额填写正数，类型决定收支方向。大类支持 `本地生活`、`购物`、`交通`、`居住`、`医疗`、`学习`、`其他`、`待分类`。旧 `餐饮`、`娱乐` 仍可导入，会合并为本地生活并保留原来的细类。CSV可选列保存细类、平台、脱敏短信凭据、接收时间与入账时分类依据；旧CSV仍可读取。含逗号或换行的字段需按 CSV 规范加双引号。优先使用 JSON 进行完整恢复，CSV 用于账目交换，不包含全部设置和关联信息。

## 在 iPhone 使用

需要先把生产构建 `dist/` 部署至 HTTPS 静态站点，再用 Safari 打开，选择“分享 → 添加到主屏幕”。云开发服务器启动不等于已部署到手机可访问的地址。PWA 的缓存和离线能力需要安全上下文；本地开发环境仅是验证例外。

### 使用 GitHub Pages

GitHub Free 的公开仓库可使用 GitHub Pages；私有仓库需要支持 Pages 的付费套餐。GitHub 托管程序文件；本机模式的账目留在设备，账号模式的账目发送到配置的 Supabase 项目，不写入 Git 仓库。

仓库使用 `.github/workflows/deploy-pages.yml`；Pages 的 Source 选择 **GitHub Actions**。账号版工作流要求有效公开连接配置，缺失时阻止构建发布，避免把本机版误当成账号版。完成数据库和认证配置后可通过 `main` 发布测试版本，再走完真实注册、邮箱验证和两个测试账户的隔离检查；构建成功不能替代这些验证。

GitHub 项目站点使用仓库名子路径。工作流通过 `MONEYTRAIL_BASE_PATH` 同时设置资源、PWA 启动范围与离线回退。可在本地验证本仓库的部署路径：

```sh
MONEYTRAIL_BASE_PATH=/Moneytrail-/ npm run build
MONEYTRAIL_BASE_PATH=/Moneytrail-/ MONEYTRAIL_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

普通根域名托管继续使用不带该变量的 `npm run build`。不同部署路径使用对应构建；不要把根路径部署包直接当作 GitHub 项目站点版本。更新时保留原站点地址，换地址前先导出 JSON 备份。

普通 iPhone 网页或应用不能在后台直接读取短信、微信/支付宝通知或交易历史。账号版通过用户在“快捷指令”中配置的个人自动化，将筛选后的新工行支出短信提交到自己的云端账户；配置完成前不会自动采集，也不能补读历史短信。短信触发、内容传递和锁屏运行仍需在自己的 iPhone 上验证。开通方法、令牌管理与排查步骤见 [短信自动化说明](docs/sms-automation.md)。

手动录入仍支持粘贴短信，或通过 URL 片段传入：`https://你的部署域名/#sms=<经过 URL 编码的短信文本>`。这是部署占位示例；打开后会填入文本并清除片段，仍需识别、核对和保存。自动接入使用专用 HTTPS 接口和请求正文，不把接入令牌或短信放进网页链接。

银行卡短信无法覆盖零钱、支付宝余额等全部支付场景，也可能只显示“财付通”而没有真实商户；需要账单补全和人工核对。

## 本地数据与恢复

本机模式的账目保存在当前设备、浏览器和站点对应的 `localStorage`，不上传服务器。账号模式使用按项目、用户分开的离线副本，确认的记录会同步至该账户的云端账本；配置短信接入并选择自动记账后，含义明确且通过核对规则的消费也会自动写入该账户的云端账本。退出时移除该账户的本机副本。旧本机账本需要单独备份和确认迁移，不会因登录而上传。

浏览器清理、隐私浏览、存储限制、切换域名或更换设备都可能影响未同步数据；Safari 与主屏幕应用之间也不要假定离线副本会共享。账号模式换设备前应确认“已同步”，并定期导出 JSON 备份。

备份文件包含消费明细，应自行妥善保存。读取到损坏的本地数据时，应用会保留原始内容并阻止直接覆盖；优先下载原始数据，再选择恢复或重置。保存失败不能视为修改已经生效。应用会尽力检测其他标签页造成的账本变化，并拒绝旧状态覆盖；本地存储不提供跨标签页数据库事务，建议集中在一个页面编辑。

## 后续范围

更多银行的短信格式、周报、订阅识别和多币种属于后续功能。账号版部署后还需完成真实 Supabase 项目的注册、邮件与隔离验证，以及 iPhone 短信自动化实测；日常录入、账单补全、分类、统计与备份仍需持续检验。
