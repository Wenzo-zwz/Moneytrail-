# Moneytrail · 慢慢记账

面向 iPhone 的个人消费账本：从银行短信和支付平台账单整理记录，查看每月花了多少、花在哪，以及还剩多少预算。界面适配手机，可作为 PWA 添加到主屏幕。

界面采用石墨黑、碳纤维编织纹理与铂金色数字，手机导航、表单、弹窗和主屏幕图标使用同一套深色设计。

这是使用本机存储的首版，没有后端、登录或云同步，也不需要银行卡账号、支付平台密码和 API 密钥。首次打开为空账本，不会把演示消费混入真实记录。

## 开发与验证

使用 Node.js 24（见 `.nvmrc`）和 npm。在已有检出目录工作；每个云任务已隔离，无需额外创建 Git worktree。

```sh
cd /workspace/Moneytrail-
npm ci
npm test
npm run typecheck
npm run build
npm run dev -- --host 0.0.0.0
```

开发服务器使用端口 `5173`。预览生产构建：

```sh
npm run build
npm run preview -- --host 0.0.0.0
```

生产预览使用端口 `4173`。技术栈为 React 19、TypeScript 5.9、Vite 8、Vitest，PWA 由 `vite-plugin-pwa` 生成。必需的 `npm test` 覆盖金额、短信/CSV 解析、统计和本地备份等业务规则；运行结果以当次输出为准。

浏览器冒烟测试需要 Chromium，可验证录入、导入、恢复、移动布局和离线流程：

```sh
# 首次在没有浏览器的机器上执行
npm exec playwright install chromium
npm run build && npm run test:e2e
```

本云环境已有系统 Chromium，可使用 `MONEYTRAIL_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`；默认使用 Playwright 配套浏览器。测试自行启动并清理端口 `4183` 的生产预览，不需要提前启动服务。浏览器测试受机器的浏览器能力限制，不替代必需的单元测试。

## 首版流程

1. **录入与核对**：粘贴银行消费短信，解析成待确认记录；也可以手动录入。缺少日期或商户时会提示核对，确认后才保存。
2. **账单补全**：导入微信、支付宝或通用 CSV，预览记录、修改分类，再确认保存。不同平台导出格式会变化，无法识别的行会报告，不能把导入成功视为账单已经完整。
3. **处理重复**：相同来源、交易类型和交易编号的重复导入可以识别，退款与原消费即使共享编号也分别保留；金额、类型和时间接近的记录只提示疑似重复，由用户核对。同一笔美团消费即使同时出现在微信账单和银行短信中，也只应记一次。
4. **查看本月**：查看支出、退款、分类和预算；月预算为各月共用的固定额度。账单核对状态由用户手动标记，不代表应用读取过全部支付渠道；相关月份的账目被修改后，需要重新核对。
5. **备份**：导出 JSON 完整备份或 CSV 账目。恢复 JSON 前校验格式，并在确认后原子替换当前账本，不先删除原数据；清空本地数据也需要确认。

金额以整数“分”保存，首版仅支持人民币。消费按交易日期计入对应月份；退款在收到退款的月份抵减支出。因此净支出为“支出减退款”，可能出现负数。转账、余额充值和信用卡还款应作为资金流转记录，不重复计入消费；信用卡购买本身计入消费。无法确定的记录应先核对。

## CSV 文件

支持 UTF-8 和 GB18030 文本 CSV。首版不读取 Excel 工作簿或加密 ZIP，需先通过支付平台取得可读取的 CSV 文件。账单中的非人民币消费不能直接按人民币金额导入。

通用模板：

```csv
日期,类型,金额,商户,分类,备注,交易编号
2026-10-01 12:30,支出,28.50,示例餐厅,餐饮,午餐,example-001
2026-10-02 09:00,退款,10.00,示例商店,购物,部分退款,example-002
```

类型为 `支出`、`退款`、`转账` 或 `收入`；金额填写正数，类型决定收支方向。分类支持 `餐饮`、`购物`、`交通`、`居住`、`娱乐`、`医疗`、`学习`、`其他`、`待分类`。含逗号或换行的字段需按 CSV 规范加双引号。优先使用 JSON 进行完整恢复，CSV 用于账目交换，不包含全部设置和关联信息。

## 在 iPhone 使用

需要先把生产构建 `dist/` 部署至 HTTPS 静态站点，再用 Safari 打开，选择“分享 → 添加到主屏幕”。云开发服务器启动不等于已部署到手机可访问的地址。PWA 的缓存和离线能力需要安全上下文；本地开发环境仅是验证例外。

### 使用 GitHub Pages

GitHub Free 的公开仓库可使用 GitHub Pages；私有仓库需要支持 Pages 的付费套餐。公开源代码不意味着上传用户账目，账目仍保存在设备本地。

仓库已准备 `.github/workflows/deploy-pages.yml`。将代码推送到 `main` 后，在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**，再运行 **Deploy Moneytrail to GitHub Pages** 工作流。成功后，以 Pages 设置或工作流给出的 HTTPS 地址为准，用 iPhone Safari 打开并添加到主屏幕。目前准备配置不代表已经推送或上线。

GitHub 项目站点使用仓库名子路径。工作流通过 `MONEYTRAIL_BASE_PATH` 同时设置资源、PWA 启动范围与离线回退。可在本地验证本仓库的部署路径：

```sh
MONEYTRAIL_BASE_PATH=/Moneytrail-/ npm run build
MONEYTRAIL_BASE_PATH=/Moneytrail-/ MONEYTRAIL_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

普通根域名托管继续使用不带该变量的 `npm run build`。不同部署路径使用对应构建；不要把根路径部署包直接当作 GitHub 项目站点版本。更新时保留原站点地址，换地址前先导出 JSON 备份。

普通 iPhone 网页或应用不能在后台直接读取短信、微信/支付宝通知或交易历史。当前支持粘贴短信，也支持通过 URL 片段传入：`https://你的部署域名/#sms=<经过 URL 编码的短信文本>`。这里的域名是部署占位示例，不是已上线地址。打开后会进入录入页、填入文本并清除 URL 片段；仍需手动识别、核对和保存，不会自动入账。

片段入口已实现，可作为后续“快捷指令”配置的接收端。收到短信后的自动触发、iOS 内容传递和锁屏表现尚未完成真机验证，也不能自动补读历史短信。

银行卡短信无法覆盖零钱、支付宝余额等全部支付场景，也可能只显示“财付通”而没有真实商户；需要账单补全和人工核对。

## 本地数据与恢复

账目保存在当前设备、浏览器和站点对应的 `localStorage`，不会由本应用自动上传服务器。浏览器清理、隐私浏览、存储限制、切换域名或更换设备都可能影响数据；Safari 与主屏幕应用之间也不要假定账本会自动共享。定期导出 JSON，换设备或入口时用备份迁移。

备份文件包含消费明细，应自行妥善保存。读取到损坏的本地数据时，应用会保留原始内容并阻止直接覆盖；优先下载原始数据，再选择恢复或重置。保存失败不能视为修改已经生效。应用会尽力检测其他标签页造成的账本变化，并拒绝旧状态覆盖；本地存储不提供跨标签页数据库事务，建议集中在一个页面编辑。
