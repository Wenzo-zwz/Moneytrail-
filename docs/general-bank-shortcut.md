# 通用银行模板 v2：包含招商银行

v2 覆盖农业银行、中国银行、建设银行及招商银行，储蓄卡和信用卡共用一份指令，均先进入待确认。工行继续使用其独立模板。

**v2 的 iCloud 安装链接尚未发布。** 已审核的[农中建 v1 模板](https://www.icloud.com/shortcuts/90ce49ad282d490481700cfe8868b82d)继续供原三家银行安装，但它不会转发招商银行短信。网页更新无法远程修改手机里的旧指令。

## 用 iPhone 更新并分享一次

1. 登录 Moneytrail，在“短信自动记账”的“银行”中选“招商银行”，查看“制作与分享模板（仅需一次）”，点击“复制匹配规则”。复制内容不含个人令牌。
2. 从上面的 v1 链接添加空白副本，或复制一份未填个人令牌的 v1，重命名为 **MoneyTrail 通用银行记账**。保留原个人指令。
3. 找到已有的“匹配文本”，把规则整体替换为 v2。输入仍选“短信正文”，关闭区分大小写；保留后续“如果匹配文本有任何值”、请求和通知，避免重复添加筛选操作。
4. 分享副本最上面的令牌文本及导入问题的默认答案均保持空白。点“分享 → 复制 iCloud 链接”，核验实际产物后再发布一键安装入口。
5. 每位使用者在个人副本填写本人的有效令牌。不同人不共用令牌，不把个人副本或真实短信写进公开模板。

Mac 用户可下载[未签名 v2 源文件](https://wenzo-zwz.github.io/Moneytrail-/shortcuts/moneytrail-general-bank-v2.unsigned.plist)，使用页面的“复制 Mac 签名命令”签名后导入。未签名 XML 不是可直接安装的 iPhone 快捷指令。

## 朋友首次接入

使用自己的账号及令牌，在手机安装已交付的 v2，或按上面步骤更新个人副本。选择银行不会更换令牌，旧三行模板链接不能代替 v2 更新。

在“快捷指令 → 自动化 → 信息”选择实际发送招商银行消费短信的发件人，**“信息包含”留空**，按设备选项设为立即运行。部分信用卡短信只写“招行信用卡”，填“招商银行”会漏触发；正文由模板在手机上继续筛选。先从自动化输入获取短信文本，再运行 **MoneyTrail 通用银行记账**，明确传入该文本。

等待下一条真实消费短信，回网页刷新接收状态。收到后先待确认，核对或补齐金额、日期、商户和消费或转账类型，再确认保存。不要为验收额外消费，也不要改写原文绕过规则。

官网短信端口示例包括 95555、1065795555、106941995555，端口不止这些，以朋友实际短信为准。依据：[服务热线](https://m.cmbchina.com/hotline.html)、[信用卡短信端口公告](https://cc.cmbchina.com/detail/2024110205gg_news.htm)。号码示例不能代替正文校验。

## 格式与待确认

新增适配针对提供的两种样例：带“〖招商银行〗”来源和“快捷支付”的账户通知，以及完整“您尾号…的招行信用卡于…消费人民币…元”句式。白角括号和没有独立尾签名的信用卡句式需要 v2；旧模板不具备这些条件。

金额从扣款动作旁提取，余额不作为消费。月、日、时、分需有效；缺少年份时按接收时间推断并提示核对，历史或未来时间同样需确认。渠道描述不等于具体商户，未提供商户时明确待补充。未知或不完整格式仍可能保留原文，不给出猜测草稿。

样例不代替朋友实际短信、手机触发、导入和授权验收。所有招商银行记录保持待确认，即使账户选择自动记录也不会直接入账。

## 维护与交付

v1 配置、JSON、XML 和审核过的安装链接保留不变。v2 配置为 `public/shortcuts/general-bank-profile.json`，源为 `shortcuts/moneytrail-general-bank.template.json`；`scripts/build-bank-shortcut.py` 同时构建和检查两版。模板仍使用原生产接口及 `p_token`/`p_message`，空白令牌和通知分支不变。

v2 的 `url` 暂为空；实际分享产物审核前，不给招商银行提供旧版或占位安装链接。其他 Supabase 部署不提供本生产项目的安装或制作内容。后续按[首次试用清单](automatic-bookkeeping-rollout.md)记录真实短信及新用户验收。

## 云端验证（2026-11-17）

生产项目已应用 `20261116164816_cmb_review_intake.sql` 及 `20261117113755_cmb_sms_formats.sql`。使用两条提供的格式样例进行只读函数验证：快捷支付提取 11415 分、04-09 06:43、支付描述 `支付宝-payee`；信用卡提取 25605 分、12-24 18:04、提示待补充商户，两者均要求确认。样例日期按各自指定的接收日期验证，不代表实际收到过这些短信。

37 个已有、此次不涉及的业务函数定义指纹保持一致；新增私有辅助函数没有授予匿名或登录角色执行权限。验证未向真实用户的账本或收件箱写入样例。上述验证不代替新 iCloud 共享产物审核及朋友手机上的真实短信触发验收。
