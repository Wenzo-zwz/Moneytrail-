# iPhone 银行短信自动接入

Moneytrail 通过 iPhone 的“快捷指令”个人自动化，把选定的银行消费短信发送到你当前的慢慢记账账户。手机需要配置一次；仅把网页添加到主屏幕，不会获得读取短信的权限。

## 普通用户：安装现成模板

工行用户可直接安装现成模板，无需建立 Supabase、执行 SQL，或手工配置接口和通知分支。当前共享模板仍只用于工行消费短信；系统兼容性以 Apple 导入提示为准。新增农行、中行、建行接收范围及配置说明见下一节，不能直接套用工行模板。

1. 登录 [Moneytrail](https://wenzo-zwz.github.io/Moneytrail-/)，进入“短信自动记账”，阅读转发说明后启用个人接入，复制仅显示一次的个人令牌。有效旧令牌可继续使用；更换会使旧令牌失效，需要更新仍在使用的设备和快捷指令。
2. 用 iPhone 打开 [MoneyTrail 慢慢记账模板](https://www.icloud.com/shortcuts/86d33de8ff704d6581c173b82f3f4f21)，在导入问题中填写自己的令牌。模板已包含筛选、POST 请求和中文通知。保留模板名称 `MoneyTrail 慢慢记账`，便于下一步选择。
3. 打开“快捷指令”→“自动化”→新建“信息”：发件人选择真实银行号码（工行通常为95588，以实际短信为准），信息包含“支出”，选择“立即运行”。添加“从输入中获取文本”，输入选“快捷指令输入”；再添加“运行快捷指令”，选择上述模板，并明确将上一步提取的文本作为输入。导入普通快捷指令不会自动建立这条个人自动化。
4. 等待一条新的真实消费短信，回网页点击“刷新接收状态”，核对最近接收时间和收件箱状态。`recorded` 表示已入账，`pending` 表示已接收待确认，`duplicate` 表示同一正文最近24小时已接收过、本次未新增；它不保证原记录已经入账。不要用虚构消费验证通知。

“接入已启用”不表示模板已安装或短信触发已设置。旧接收时间也不证明新模板已经验证；网页只展示服务器收到的信息，不假装探测手机设置。当前模板没有不入账探针模式。断网、非JSON、缺少状态或HTTP失败可能在通知前中断，不能保证每种失败都有自定义中文通知；结果不明时请核对账本，再决定是否补录。

发布的模板静态审核记录：24个操作，导入问题绑定第一条令牌文本，共享文本和默认答案为空，无个人令牌；请求、变量引用和四层条件结构已核对。该审核不替代新用户在真实iPhone上的导入、授权与短信触发测试。模板保留的输入类型包括文本及App内容；自动化仍应明确提取并传入短信文本。

模板固定连接 Moneytrail 生产项目。自行部署到其他项目时必须使用配套模板或下面的高级手动配置，不要把其他项目的个人令牌填入此模板。安装链接不包含用户令牌、短信或账户ID；个人令牌只能在用户自己的导入配置中填写。

以下数据库初始化和接口手工配置章节供应用维护者及自行部署者参考。

## 四大行的接入范围

在网页「在 iPhone 上接入」中选择银行。选择只切换说明，不会更换令牌或修改手机自动化。

| 银行 | 当前接收和识别范围 | 手机配置 |
| --- | --- | --- |
| 工商银行 | 继续按原有完整格式识别；明确消费可自动入账 | 可安装现成工行模板 |
| 农业银行 | 已开放带唯一银行签名的支出短信接收；有界信用卡历史格式可提取草稿，仍待确认 | 查看农行手动说明 |
| 中国银行 | 已开放带唯一银行签名的支出短信接收；缺少当前真实正文样本，未知格式保留待确认 | 查看中行手动说明 |
| 建设银行 | 已开放带唯一银行签名的支出短信接收；有界历史批扣格式可提取草稿，仍待确认 | 查看建行手动说明 |

新增三行目前均先待确认，即使账户选择了「自动记录明确消费」也不会直接入账。已登记银行不表示该银行全部储蓄卡、信用卡和地区短信格式都通过实测。缺商户或时间不会编造字段；无法提取的短信保留原文供核对。

新增三行的接收门槛要求金额紧跟扣款动作，允许中间出现空格、冒号、「金额为」及人民币/RMB/CNY等币种说明。明确外币、纯收入、营销和仅开通消费通知的消息不会进入队列。动作与金额之间夹有其他商户描述或长句的变体尚需真实样本适配，不能保证进入待确认；不要修改原文来绕过检查。

其他三行的手机配置：发件人选择实际发送该银行短信的号码，「信息包含」可填「元」，选择立即运行；提取短信文本后，筛选一项完整银行签名、至少一个支出关键词（支出、消费、扣款、扣费、批扣、代扣、转出、支取），并排除验证码等安全短信。银行别名之间用「任一」，不同条件组之间用「全部」，不能要求正文同时包含四家银行。网络请求沿用下方 POST 地址、公开密钥、个人令牌和短信正文变量。金额单位不是「元」或没有银行签名的变体不在本轮接收保证范围内，请提供脱敏样本核验。

常见发送号码仅供选择参考，必须以实际短信为准：工行95588；农行95599、1069095599、10690955998；中行95566；建行95533、106980095533。依据：[农行号码公告](https://www.abchina.com/cn/PersonalServices/SvcBulletin/202508/t20250827_2458070.htm)、[中行交易通知公告](https://www.boc.cn/bcservice/bi2/202403/t20240327_24804813.html)、[建行官方FAQ](https://creditcard.ccb.com/faq/20111126_924470564/questionlist_1.html)。这些号码不能代替银行正文格式校验。

本轮有界草稿提取参考[农行官方信用卡历史手册](https://www.abchina.com/cn/creditcard/xykts/201602/W020200724518582815201.pdf)和[建行2010年账户通知报道](https://e.ccb.com/chn/2010-06/23/article_2021082106133178863.shtml)。历史示例中的正文有时省略银行签名，本轮仍要求接收原文带签名，不得人为添加或改写签名来绕过范围校验。真实当前短信和锁屏转发尚待逐行验证。

共享模板无法由网页更新手机上已安装的版本。当前 iCloud 链接有「工商银行＋支出」筛选，保留工行版标识；要发布四行通用安装包，需要在 iPhone 修改筛选后重新共享并核验新链接。现有有效个人令牌可以沿用。

目前针对工商银行的 `月日时分支出(内容)金额元` 短信做了识别。例如：

```text
尾号xxxx卡10月22日19:27支出(转账财付通-群收款)30.90元，余额8xxxx元。【工商银行】
```

这条记录的金额是 **30.90 元**，余额不会作为消费金额。“财付通-群收款”每次进入**待确认**，由你选择消费或转账后再保存。待确认的记录不计入每月消费。

选择“自动记录明确消费”后，格式、金额、时间有效的普通工行消费支出可以直接入账。餐饮和娱乐合并为“本地生活”，同时保存细类和消费平台：美团、三快平台公司及已知截断名称默认本地生活，细类未知不会阻止入账；外卖、餐厅、足浴等明确用途可细分。京东、淘宝、天猫、拼多多默认购物，只有平台名称时细类保持未知。药店、酒店、打车、教材等明确用途仍分别归医疗、居住、交通、学习，不因平台名称覆盖实际用途。只有“财付通”“支付宝”等其他渠道、群收款、用途不明的个人转账仍待确认。具体商户可辨认但大类未知时，先入账为“待分类”。

| 分类 | 常见依据 |
| --- | --- |
| 本地生活 | 外卖、餐厅、饭店、咖啡、奶茶、火锅、按摩、足浴、剧本杀、密室、台球、电影等；美团平台默认此大类 |
| 购物 | 烟酒、副食、超市、便利店、服饰、服装、数码、日用品；京东、淘宝、天猫、拼多多默认购物 |
| 交通 | 滴滴、出租车、公交地铁、铁路、加油、停车、通行费 |
| 居住 | 酒店、房租、水电燃气、物业、宽带、话费和手机充值 |
| 医疗 | 医院、药房药店、诊所、体检、买药 |
| 学习 | 课程、培训、教材、书店、学费、考试 |

除个人具体商户规则采用规范化名称精确匹配外，上述关键词采用包含匹配：`张记烟酒` 和 `烟酒专卖店` 都能命中“烟酒”，不要求完整出现“烟酒副食”。不会自动把单字“烟”“酒”“店”“馆”扩展成类别，也不会进行拼写相似度推测。SPA 忽略大小写和全半角，但要有 ASCII 字母边界，以免把 `Space咖啡` 误分为娱乐。

关键词并不保证用途百分之百准确。多组同时出现时沿用医疗、居住、交通、学习、本地生活、购物的优先级，例如“医院按摩”仍属医疗；个人具体门店规则可以纠正例外。美团平台名称缺少门店、订单内容时无法可靠推断细类，程序默认大类为本地生活；既不使用平台旧个人规则，也不能给整个平台新建永久具体用途规则。

本地生活细类包括餐饮、外卖、咖啡奶茶、休闲娱乐、按摩足疗、剧本杀密室、桌游台球、电影影音、景区游玩等，也可手动填写不超过40字的细类。旧餐饮、娱乐可读取或导入，自动归并为本地生活并保留餐饮、休闲娱乐细类。月度统计可展开大类查看细类净支出，包括“未细分”，合计与大类一致；账目搜索覆盖细类和平台。关联退款继承原消费的分类、细类和平台，不复制原消费的短信凭据。

明确写为“微信零钱充值”“支付宝余额充值”“本人账户互转”“本人账户间转账”“信用卡还款”的描述可自动记录为转账，不计消费；话费充值归生活消费。其他转账、投资、退款、失败或异常时间仍需核对。也可选择全部先待确认。

商户名支持配对的内嵌中英文括号，例如 `消费财付通-示例商贸（烟酒副食）`。交易金额与余额分别识别，支持正确分组的千位逗号；余额不会参与支出计算。其他银行、退款及收入格式暂不保证支持。

对于完整工行短信中的 `支出(消费财付通-示例台球俱乐部（青年路店)88元…【工商银行】`，可以在解析时补齐门店缺失的单个全角右括号。此容错仅适用于原文银行外层 ASCII 括号完整、商户内部恰有一个全角开括号、门店标签为 1–40 字且以“店／营业部／支行／分行”结尾的情况；金额、日期、币种、重复和群收款检查照常执行。一般的缺括号、多括号或多事件仍需人工核对。补齐只影响解析内容，未处理短信的原文不会被改写。

## 2. 在自己的账户生成接入令牌

1. 打开 [Moneytrail](https://wenzo-zwz.github.io/Moneytrail-/)，登录准备接收短信的账户。
2. 点击页面顶部的“短信自动记账”，或“设置”页第一张卡片里的“打开短信自动记账”，选择“自动记录明确消费”或“全部先待确认”。
3. 阅读短信转发说明，点击“同意转发并启用”。在“接入令牌，仅显示这一次”窗口点击“复制令牌”，妥善保存后点击“我已保存”。待会儿将它填写到快捷指令。

令牌只在生成时完整显示。它与当前账户绑定，数据库只保留令牌的哈希，之后无法取回原文。令牌遗失时重新生成，并同步替换手机里的旧令牌；旧令牌随即失效。

不要把令牌发给他人、放进截图、GitHub 仓库或网页链接。持有它的人无法读取你的账本，但可以向你的账户提交短信记录。停止使用时可在页面关闭接入。

## 3. 在 iOS 18.6.2 创建个人自动化

以下操作需要在 iPhone 自带的**快捷指令** App 中完成。系统语言和版本不同，按钮名称可能略有差异。

### 设置触发条件

1. 打开“快捷指令”→“自动化”→右上角 `＋`，创建个人自动化。
2. 选择“信息”或“收到信息时”。
3. “发件人”选择你手机里**实际发送工行消费短信的号码**。常见为 `95588`，以短信详情为准。
4. “信息包含”填写 `支出`，选择**立即运行**。
5. 进入添加操作的页面。如果页面让你选择已有快捷指令，选择新建空白快捷指令。

“信息”触发器匹配之后收到的新短信，不能补读历史短信。可以先保留运行通知，方便观察是否触发。

### 取得短信正文并过滤

1. 添加“从输入中获取文本”，输入选择自动化传入的“快捷指令输入”或“信息”正文变量。
2. 把结果设为变量，例如命名为 `短信正文`。
3. 用“如果”操作限制：正文包含 `工商银行`，且包含 `支出`，且不包含 `验证码`、`动态口令`、`一次性密码`。不满足时停止快捷指令。

如果“如果”界面不能一次填写多个条件，可以嵌套多个“如果”，只把下一步的网络请求放在全部条件满足的分支。短信内容要使用上一步取得的**变量**，不要把某条短信写成固定文字。

### 添加发送操作

在过滤通过的分支添加“获取 URL 内容”：

| 设置 | 填写内容 |
| --- | --- |
| URL | `https://ojcgabicpjipwpvwolzn.supabase.co/rest/v1/rpc/moneytrail_receive_sms` |
| 方法 | `POST` |
| 标头 `apikey` | 在页面的“iPhone 配置步骤”中点击“复制公开密钥”取得的值 |
| 标头 `Content-Type` | `application/json` |
| 请求正文类型 | `JSON` |
| JSON 字段 `p_token`，类型“文本” | 你刚生成的接入令牌 |
| JSON 字段 `p_message`，类型“文本” | 选择 `短信正文` 变量 |

请求内容的结构如下；在快捷指令里逐项添加字段，不要直接把这段带占位文字的 JSON 当作短信正文：

```json
{
  "p_token": "在此填写你自己的接入令牌",
  "p_message": "在此选择短信正文变量"
}
```

这里的 `apikey` 是可公开的项目连接 key；`p_token` 是仅供你使用的短信接入令牌，两者用途不同。无需填写登录密码、账户访问令牌或 `Authorization` 标头。

若你部署到其他 Supabase 项目，URL 和公开 key 必须一起改成该项目的值。设置完成后保存自动化。

## 4. 用真实消费短信验证

保持自动化使用传入的**短信正文变量**，等待下一条符合条件的真实工行消费短信；不要把上面的格式示例当作实际消费发送。

1. 收到新短信后，核对快捷指令的中文通知。`recorded` 表示已入账，`pending` 表示已接收待确认，`duplicate` 表示近期接收过同一正文、这次未新增。网络或接口错误也可能使流程在通知前中断。
2. 回到 Moneytrail 的“短信自动记账”，点击“刷新接收状态”，检查最近接收时间。
3. 在短信收件箱核对该笔金额、商户、时间及状态；已入账的记录再到账本核对。群收款和用途不明的转账应保持待确认。
4. 如果确有漏记，先核对账本及收件箱，再用那条真实漏记短信的原文补录或重发。不要修改金额、时间或商户来绕过重复检查。

短信触发、输入变量、首次联网授权和锁屏运行情况仍需要在自己的 iPhone 上实测。历史接收时间、网页检查及手动重发都不能代替新短信的自动触发验证。

同一账户在 24 小时内重复提交完全相同的短信文字，只保留一次接收结果。自动记账时，如果最新账本已有同类型、同金额且交易时间相差不超过 10 分钟的记录，新短信会转为待确认并提示疑似重复，不会直接丢弃；确为另一笔付款时仍可确认保存。

这个提示不能覆盖时间差更大、时间或金额不一致的跨渠道记录。同一笔消费同时出现在短信和微信、支付宝账单中时，仍需人工核对，避免重复计算。

## 5. 处理待确认和同步

升级规则后，可在“分类与历史整理”点击 **“预览待确认短信”**。页面显示每笔金额、分类、处理依据以及可入账和保留确认的笔数；预览不写入账本。确认后点击 **“确认应用可入账记录”**，只处理这次预览列出的记录，新到短信不在其中。群收款、不明转账、疑似重复继续待确认；规则或记录变化时需要重新预览，重复提交不会重复加账。无论当前选择自动记录还是全部先待确认，都可主动执行这次批量处理，未来短信的接收方式保持原设置。

重新识别使用原短信和原接收时间，可恢复旧规则因余额千位逗号、内嵌括号而失败的短信，无需重新转发。尚未提交的单条核对修改不带入批量处理。成功入账前会保存脱敏凭据，再移除原文；已入账的记录不会重新处理。

点击 **“预览账本待分类”**，可给已经入账的消费补分类：只处理类型为消费支出、原分类为“待分类”的记录，保留已有分类、金额、日期、备注及关联。预览后点击 **“确认更新分类”**，更新原记录而不新增流水；相关月份需要重新核对。当前页面可 **“撤销本次分类”**，恢复这些记录原来的分类。离开页面后不保留撤销列表，后续修改过的记录不允许旧撤销覆盖；撤销也不会恢复已经失效的月份核对状态。

首次遇到未知的具体商户，在手动新增、修改账目、导入预览或单条短信核对中明确选择分类或细类后，会默认勾选 **“以后这家都这样分类”**，可取消勾选。确认保存时，所选大类和细类才会作为当前账户的规则保存；“未细分”也可以明确记住。只补备注、直接导入原有分类、取消编辑、恢复备份、批量分类或撤销都不会自动教会规则。导入预览里的选择要等该笔记录被勾选并真正保存后才生效。

同一家商户通过财付通、支付宝、抖音支付等已知渠道付款，去掉前缀并统一全半角后会沿用相同规则，网页粘贴短信和自动接收短信都适用。例如 `抖音支付-巷口体验馆（城东店）` 可以复用 `巷口体验馆(城东店)` 的规则；`巷口体验馆(城西店)` 仍分别确认。匹配不会改写原商户描述或脱敏凭据。群收款、纯渠道、用途不明的个人转账和只有平台名称的记录不能生成商户记忆，把原来的群收款改成店名也不会自动学习。

手动新增账目时，输入已记住的具体商户也会自动带出大类和细类；继续改成另一分店时会撤回自动分类。已经明确手选的分类不会被自动结果覆盖。

账户账本的记忆选择与账目一起保存到本机，离线重开后仍会等待同步；联网后两者一起提交。看到“已同步”后才表示云端已接收，其他设备才能沿用。如果同步冲突，先按提示核对账本，不要把本机保存提示当作规则已经发布。个人规则读取失败时会显示重试入口，日常账目仍可编辑，识别结果需要重新核对；“预览账本待分类”会等待规则读取成功，以免漏用已有规则。

账本尚未同步时，个人规则的直接保存和删除会暂时停用，避免旧的待同步选择覆盖刚修改的规则。如果规则数量已满或这次记忆有误，可在“个人商户分类规则”的待同步列表中点击 **“取消这次待同步记忆”**；这会保留账目，只移除该笔尚未提交的学习选择。等账目同步完成后，再删除不需要的云端规则并重试。

在 **“个人商户分类规则”** 中可读取规则、选择“编辑规则”修改大类与细类、或删除规则。输入商户时页面会显示去掉支付前缀后的“匹配名称”，可检查是否仍包含正确的分店。已有美团平台规则仍可查看和删除，但不会覆盖程序的平台默认大类。保存或删除规则会清除旧的历史预览，账目不会立即批量变化；请重新点击“预览账本待分类”，只在核对预览后确认更新。已经有分类的账目会保留原分类。

在待确认记录中核对金额、日期、商户、分类和交易类型，再点击“确认并记入账本”。群收款可按实际用途选择“支出”或“转账”；转账不计入每月消费。无法识别的工行支出短信可以手动填写字段，或点击“忽略此条”。

确认保存会追加到当前账户的最新云端账本，再刷新本机副本。若当前设备有尚未同步的编辑或版本冲突，先完成同步、核对或备份，再处理短信，避免把两个版本混在一起。

自动入账也会更新云端版本。其他设备持有旧版本时可能需要刷新；如有未同步修改，按页面提示核对，保留需要的备份。

## 收不到时检查

- **接收时间未更新**：检查自动化是否开启、银行号码及 `支出` 条件是否匹配、是否选择立即运行，以及正文变量是否为空。
- **请求报错**：检查网络、URL、`POST`、两个 JSON 字段名、公开 key 和接入令牌。重新生成令牌后，手机里的值也要替换。
- **页面提示尚未开通**：确认上述 SQL 文件都已在同一个 Supabase 项目执行成功。
- **选择自动记录但普通消费仍显示格式不支持**：确认已执行前四份及第 5 份 SQL，再预览待确认短信；配对的商户括号和千位逗号均应支持。
- **提示“自动入账规则尚未升级”**：在 SQL Editor 执行第 5 份 SQL 后重试预览；缺少新接口时，旧收件箱和单条确认仍可使用。
- **显示待确认但本月支出没变化**：待确认不计入账本。明确消费可预览后批量入账；群收款、不明转账或疑似重复仍需核对后保存。
- **看到旧版页面**：出现“发现新版本”时，先保存正在填写的内容并确认账目同步状态，再点击“更新并重新打开”。早期没有更新提示的版本，需要关闭 Moneytrail 主屏幕应用及相关 Safari 标签页后重新打开；保留网站数据，以免丢失尚未同步的账目。
- **断网时没有入账**：快捷指令请求需要联网，这个接入没有自动离线重试队列。可恢复网络后重新提交该条短信，或手动补录。
- **接收被限制**：每个账户每日最多接收 100 条，待确认最多 200 条。先处理积压记录；达到限制的请求不会被当作已成功接收。

## 短信数据保存范围

只有配置的自动化运行时，筛选后的正文才会发送到你当前的慢慢记账账户。服务器拒收验证码和不符合接入范围的短信。待确认记录会保留原文供你核对，其中可能包含卡尾号和余额。今后自动入账、单条确认、预览后批量入账和重新识别入账前，均会把脱敏凭据长期保存到账本：隐藏卡号尾号、账号和余额，保留交易描述、消费金额、日期时间与银行签名，并保存接收时间、入账时分类依据和规则版本。手动粘贴短信解析也会生成脱敏凭据。凭据按账本访问权限隔离，随正常编辑、JSON备份和CSV导出保留，删除账目或替换备份时可一并删除或替换。

成功入账后，收件箱的完整原文仍被移除；忽略时不保存账目或凭据。处理完成的接收记录会在后续接收时清理接收时间早于30天的元数据，但不清理账本内脱敏凭据。手机上的原短信不会被网页删除。此功能上线前已清除的短信原文不能从普通账本/备份/指纹恢复，也不会伪造历史凭据。

脱敏凭据保住短信实际提供的信息，无法补出原短信没有的订单内容。仅写“美团/三快”时，仍不知道是外卖还是按摩；后续细分需要支付账单、订单信息或用户备注。当前大类、细类和平台可独立调整，查看“入账时分类依据”时应理解为当时记录，不是用户后来修改类别的理由。

短信接入令牌只能提交到绑定账户，不能读取账本、修改账户权限或进入管理员后台。账户登录后也只能查看和处理自己的短信队列。数据库管理员仍可能访问云端数据，独立账户不等于端到端加密。

短信中的银行名称和本地发件人条件用于筛选，不构成银行签名认证。不要把接入令牌当作公开 key 分享。银行卡短信也无法覆盖微信、支付宝余额等所有付款，仍需定期导入账单并核对。
