# iPhone 银行短信自动接入

Moneytrail 通过 iPhone 的“快捷指令”个人自动化，把选定的银行消费短信发送到你自己的 Supabase 项目。手机需要配置一次；仅把网页添加到主屏幕，不会获得读取短信的权限。

目前针对工商银行的 `月日时分支出(内容)金额元` 短信做了识别。例如：

```text
尾号xxxx卡10月22日19:27支出(转账财付通-群收款)30.90元，余额8xxxx元。【工商银行】
```

这条记录的金额是 **30.90 元**，余额不会作为消费金额。“财付通-群收款”每次进入**待确认**，由你选择消费或转账后再保存。待确认的记录不计入每月消费。

开启“自动记账”后，支持格式中含义明确的消费可以直接入账；转账、充值、提现、还款和无法确定的记录仍需核对。也可以选择所有短信都先待确认。其他银行、退款及收入格式暂不保证支持。

## 1. 先开通数据库功能

已有账号账本的项目，保留之前的数据表和 SQL 执行结果。在 Supabase **SQL Editor** 新建查询，依次执行以下两个文件的**完整内容**：

1. [202610220003_sms_parser.sql](../supabase/migrations/202610220003_sms_parser.sql)
2. [202610220004_sms_automation.sql](../supabase/migrations/202610220004_sms_automation.sql)

每份文件执行成功后再执行下一份。可以删除编辑器中已经执行过的文字以便粘贴新查询；不要删除原来的账本表或管理员设置。新项目还需先完成 [账号账本配置](cloud-accounts.md)。

这条接入方式不需要部署 Edge Function，也不需要提供数据库密码、`service_role` 或 Secret key。网页更新和数据库迁移是两件事，网页发布不会替你执行 SQL。

## 2. 在自己的账户生成接入令牌

1. 打开 [Moneytrail](https://wenzo-zwz.github.io/Moneytrail-/)，登录准备接收短信的账户。
2. 进入“短信自动记账”，选择“自动记录明确消费”或“全部先待确认”。
3. 阅读短信转发说明，点击“同意转发并启用”。在“接入令牌，仅显示这一次”窗口点击“复制令牌”，妥善保存后点击“我已保存”。待会儿将它填写到快捷指令。

令牌只在生成时完整显示。它与当前账户绑定，数据库只保留令牌的哈希，之后无法取回原文。令牌遗失时重新生成，并同步替换手机里的旧令牌；旧令牌随即失效。

不要把令牌发给他人、放进截图、GitHub 仓库或网页链接。持有它的人无法读取你的账本，但可以向你的账户提交短信记录。停止使用时可在页面关闭接入。

## 3. 在 iOS 18.6.2 创建个人自动化

以下操作需要在 iPhone 自带的**快捷指令** App 中完成。系统语言和版本不同，按钮名称可能略有差异。

### 设置触发条件

1. 打开“快捷指令”→“自动化”→右上角 `＋`，创建个人自动化。
2. 选择“信息”或“收到信息时”。
3. “发件人”选择你手机里**实际发送工行消费短信的号码**。常见为 `95588`，以短信详情为准。
4. “信息包含”填写 `支出`，选择**立即运行**。
5. 进入添加操作的页面。如果页面让你选择已有快捷指令，选择新建空白快捷指令。

“信息”触发器匹配之后收到的新短信，不能补读历史短信。可以先保留运行通知，方便观察是否触发。

### 取得短信正文并过滤

1. 添加“从输入中获取文本”，输入选择自动化传入的“快捷指令输入”或“信息”正文变量。
2. 把结果设为变量，例如命名为 `短信正文`。
3. 用“如果”操作限制：正文包含 `工商银行`，且包含 `支出`，且不包含 `验证码`、`动态口令`、`一次性密码`。不满足时停止快捷指令。

如果“如果”界面不能一次填写多个条件，可以嵌套多个“如果”，只把下一步的网络请求放在全部条件满足的分支。短信内容要使用上一步取得的**变量**，不要把某条短信写成固定文字。

### 添加发送操作

在过滤通过的分支添加“获取 URL 内容”：

| 设置 | 填写内容 |
| --- | --- |
| URL | `https://ojcgabicpjipwpvwolzn.supabase.co/rest/v1/rpc/moneytrail_receive_sms` |
| 方法 | `POST` |
| 标头 `apikey` | 在页面的“iPhone 配置步骤”中点击“复制公开密钥”取得的值 |
| 标头 `Content-Type` | `application/json` |
| 请求正文类型 | `JSON` |
| JSON 字段 `p_token`，类型“文本” | 你刚生成的接入令牌 |
| JSON 字段 `p_message`，类型“文本” | 选择 `短信正文` 变量 |

请求内容的结构如下；在快捷指令里逐项添加字段，不要直接把这段带占位文字的 JSON 当作短信正文：

```json
{
  "p_token": "在此填写你自己的接入令牌",
  "p_message": "在此选择短信正文变量"
}
```

这里的 `apikey` 是可公开的项目连接 key；`p_token` 是仅供你使用的短信接入令牌，两者用途不同。无需填写登录密码、账户访问令牌或 `Authorization` 标头。

若你部署到其他 Supabase 项目，URL 和公开 key 必须一起改成该项目的值。设置完成后保存自动化。

## 4. 验证一次，再等真实消费短信

先验证网络请求和账户归属：临时用“文本”操作提供上面的脱敏示例，手动运行发送步骤。这个操作会向你的账户提交一条**测试记录**，不代表银行又扣了一笔钱。

1. 请求成功的响应包含 `accepted: true`，`status` 为 `pending`、`recorded` 或 `duplicate`。
2. 回到 Moneytrail 的“短信自动记账”刷新，检查“最近接收”时间和“短信收件箱”中的待确认记录。
3. 示例应显示 30.90 元、财付通群收款，并保持待确认。测试结束后可忽略这条测试记录。
4. 将固定的测试文字恢复为自动化传入的**短信正文变量**。
5. 等下一条真实工行消费短信，再核对自动化通知、接收时间、金额与状态。

上述手动测试只能验证提交链路。短信触发、输入变量和锁屏运行情况仍需要在自己的 iPhone 上实测，不能用网页测试代替。

同一账户在 24 小时内重复提交完全相同的短信文字，只保留一次接收结果。自动记账时，如果最新账本已有同类型、同金额且交易时间相差不超过 10 分钟的记录，新短信会转为待确认并提示疑似重复，不会直接丢弃；确为另一笔付款时仍可确认保存。

这个提示不能覆盖时间差更大、时间或金额不一致的跨渠道记录。同一笔消费同时出现在短信和微信、支付宝账单中时，仍需人工核对，避免重复计算。

## 5. 处理待确认和同步

在待确认记录中核对金额、日期、商户、分类和交易类型，再点击“确认并记入账本”。群收款可按实际用途选择“支出”或“转账”；转账不计入每月消费。无法识别的工行支出短信可以手动填写字段，或点击“忽略此条”。

确认保存会追加到当前账户的最新云端账本，再刷新本机副本。若当前设备有尚未同步的编辑或版本冲突，先完成同步、核对或备份，再处理短信，避免把两个版本混在一起。

自动入账也会更新云端版本。其他设备持有旧版本时可能需要刷新；如有未同步修改，按页面提示核对，保留需要的备份。

## 收不到时检查

- **接收时间未更新**：检查自动化是否开启、银行号码及 `支出` 条件是否匹配、是否选择立即运行，以及正文变量是否为空。
- **请求报错**：检查网络、URL、`POST`、两个 JSON 字段名、公开 key 和接入令牌。重新生成令牌后，手机里的值也要替换。
- **页面提示尚未开通**：确认两个新 SQL 文件都已在同一个 Supabase 项目执行成功。
- **显示待确认但本月支出没变化**：先核对并保存；待确认本来就不计入账本。
- **看到旧版页面**：关闭 Moneytrail 主屏幕应用及相关 Safari 标签页后重新打开；不要清除网站数据，以免丢失尚未同步的账目。
- **断网时没有入账**：快捷指令请求需要联网，这个接入没有自动离线重试队列。可恢复网络后重新提交该条短信，或手动补录。
- **接收被限制**：每个账户每日最多接收 100 条，待确认最多 200 条。先处理积压记录；达到限制的请求不会被当作已成功接收。

## 短信数据保存范围

只有配置的自动化运行时，筛选后的正文才会发送到你自己的 Supabase 项目。服务器拒收验证码和不符合接入范围的短信。待确认记录会保留原文供你核对，其中可能包含卡尾号和余额；保存或忽略后移除原文。处理完成的接收记录会在后续接收时清理超过 30 天的元数据。

短信接入令牌只能提交到绑定账户，不能读取账本、修改账户权限或进入管理员后台。账户登录后也只能查看和处理自己的短信队列。数据库管理员仍可能访问云端数据，独立账户不等于端到端加密。

短信中的银行名称和本地发件人条件用于筛选，不构成银行签名认证。不要把接入令牌当作公开 key 分享。银行卡短信也无法覆盖微信、支付宝余额等所有付款，仍需定期导入账单并核对。
