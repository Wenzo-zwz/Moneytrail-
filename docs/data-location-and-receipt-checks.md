# 数据位置与短信接收核对

## 可选本机记账

账号站点的登录页提供“仅在本机使用”。选择后，账本使用当前设备、浏览器和域名的本机存储，不要求登录，不提交账本到云端。重新打开会保留明确选择；“连接账户”才进入账号服务。

本机账本与按项目、用户分隔的账号离线副本保持独立。连接或登录账户不会自动合并本机数据；仍需先导出备份，再明确确认迁移。账户原数据和本机原副本均沿用现有保护流程。

本机模式不会停用手机中已有的短信自动化。已配置的手机指令仍可能独立向原云端账户提交短信；要停止这一行为，需要在账号短信设置停用接入，或关闭对应手机自动化。

设置中的“数据在哪里”复用原备份卡，展示当前模式、云端地址及完整 JSON 导出。最近导出时间只表示浏览器已发起下载，用户仍需确认文件保存成功。CSV 不代替完整备份，也不重置完整备份提醒。

本机非空账本从首次观察或最近完整 JSON 导出发起时间起，超过 30 天时在打开应用后提醒。没有历史导出记录时，不用最旧交易日期猜测未备份天数。每月可稍后提醒；网页关闭时不会自行弹窗。

## 当前数据流

- 截图由手机 OCR，图片不上传；截图文字用于网页核对。账号模式中，确认保存的账目会同步到所连接服务的云端数据库。
- 短信自动记账会将筛选后的短信正文发送到所连接服务，在服务器解析。待确认记录保留原文；入账后移除原文并保留脱敏凭据。忽略会移除原文，不新增账目。
- 普通注册用户使用当前服务的数据库，按账户隔离；只有自行部署并配置后端，才是使用自己配置的数据库。不能把当前账号模式宣传为“银行短信不出手机”或“每个注册用户自己的数据库”。

## 近 7 天接收核对

只读统计使用过去 168 小时内、按接收时间筛选的去重收件记录，展示这些短信当前的已处理入账、待确认和已忽略状态。它不等于期间发生的入账操作数，也不证明对应账目后来没有被删除。

本期待确认数与全部待确认数分开。统计不读取短信正文，不改变收件箱、账本或接入设置。统计读取失败时，原收件箱仍可使用。

服务器无法知道手机上没有触发、没有上传或未被接收的短信；不提供虚构的漏记数、失败上传数或“本周全部短信已记全”结论。仍需与银行或支付平台账单比对，并核对银行是否已开通动账短信、真实发件人、iOS 权限和锁屏运行。

首次实际打开短信接收页后，本设备记录该次打开时间。超过 7 天再次打开账本时，应用内提醒查看接收记录，可延后 7 天；仅按项目和账户保存提醒时间，不自动读取收件箱，也不把打开页面标为已完成对账。此版本不新增定时任务或手机推送。

## 未收到或未识别时

先检查手机自动化及网络，再查看服务端最近接收和待确认记录。支出付款详情可以用已有截图记账补录；收入、退款或转账等类型需手动核对。补录前比对金额、时间和已有记录，避免同一交易被短信和截图重复记录。当前离线提交失败没有自动补传队列。

规则清单及其发布校验见[动态银行规则](dynamic-bank-rules.md)。当前 v3 手机模板保持原样。自动缓存更新在缺失文件、锁屏权限、断网、损坏缓存及并发读写完成 Apple 真机验证前，不作为已交付能力宣传。

## 验证记录（2026-11-18）

生产只新增 `20261118012630_sms_activity_summary.sql` 的无参只读 RPC，45 个已有业务函数定义指纹保持一致。部署后的函数体与审核源一致，匿名和 PUBLIC 无执行权限；无账号上下文的调用被拒绝。数据计数与隔离在独立 PostgreSQL 夹具中验证，未读取真实用户的统计或原文，也未向账本或收件箱写入样例。

新增的已登录角色 SECURITY DEFINER 提示属于这一个受账户检查和 owner 条件约束的 RPC，其他安全提示保持原样。其权限与查询边界见[Supabase 函数安全说明](https://supabase.com/docs/guides/database/functions#security-definer-vs-invoker)。本次不新增表、定时任务、推送服务或依赖，也不改变现有短信接收和解析函数。

54 个测试文件、2,502 项测试通过；账号/本机 13 条、短信 28 条、安装与规则 14 条、分类 8 条浏览器检查通过。上述检查不代替 Apple 文件动作、iCloud 分享产物或真实手机短信的验证。
