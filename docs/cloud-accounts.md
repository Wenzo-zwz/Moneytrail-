# 独立账号与云端账本

账号版使用 Supabase 提供邮箱认证和 PostgreSQL 数据库，GitHub Pages 继续托管网页。每个账户拥有独立的账目、预算和核对状态；数据库负责限制访问权限。

本文是接入和验证说明。登录界面、构建成功或本地测试通过，都不代表已经接通托管服务。完成项目配置、数据库迁移和真实账户验证后，才能发布可用的账号版。

## 需要准备的连接信息

前端需要两个公开配置：

- `VITE_SUPABASE_URL`：Supabase 项目的 Project URL。
- `VITE_SUPABASE_PUBLISHABLE_KEY`：该项目的 Publishable key。旧项目可用 `VITE_SUPABASE_ANON_KEY` 提供 anon public key 代替。

这类公开 key 会进入浏览器程序，其权限必须由数据库策略限制。不要在前端、GitHub 仓库、构建变量或聊天中填写 `service_role`、Secret key、数据库密码或 Supabase Access Token。

没有配置时，账号服务不可用；原有本机账本不能被当作已登录的云端账户。保留本机模式用于兼容，不会自动把本机账目上传到未配置的服务。

## 1. 创建自己的 Supabase 项目

1. 打开 [Supabase Dashboard](https://supabase.com/dashboard)，登录并创建一个项目，例如 `Moneytrail`。
2. 按页面提示选择组织、地区和套餐，妥善保存数据库密码。认证和数据库可先评估免费方案；实际额度、暂停规则及费用以当前 Dashboard 为准。
3. 等待项目准备完成，从项目的连接信息或 API 设置中取得 **Project URL** 和 **Publishable key**。

应用不需要数据库密码或管理级 key。项目管理操作由项目所有者在 Dashboard 完成。

## 2. 建立数据库和访问策略

在自己的 Supabase 项目打开 **SQL Editor**，执行仓库中的完整迁移文件：

```text
supabase/migrations/202610220001_ledger_accounts.sql
```

执行成功后，确认存在：

- `public.moneytrail_ledgers`：每个用户一行账本快照，保存 `data`、`revision` 和更新时间。
- `public.save_moneytrail_ledger(p_data, p_expected_revision)`：按当前登录用户保存账本的函数。

隔离规则应同时满足：

- 未登录请求不能读取或保存账本。
- 登录用户只能查询 `user_id = auth.uid()` 的行。
- 用户不能通过直接插入、更新或删除表数据绕过保存流程。
- 保存函数从登录身份取得用户 ID，不接受浏览器传入的目标用户 ID。
- 保存必须带上已读取的版本号；版本过期时返回冲突，不能直接覆盖另一台设备的新版本。

首版云端快照上限为 **5 MB**。一次批量导入过大时需要整理后重试，或先保留本机备份；不能把本机保存成功等同于云端同步成功。

## 3. 配置邮箱登录、验证和密码重置

在 **Authentication** 的登录方式或 **Providers** 页面启用 Email 登录，按需要开启邮箱确认。账户密码交给认证服务处理，不写入账本或静态网页配置。

在认证的 URL 配置中设置：

| 配置 | 值 |
| --- | --- |
| Site URL | `https://wenzo-zwz.github.io/Moneytrail-/` |
| 生产环境允许的 Redirect URL | `https://wenzo-zwz.github.io/Moneytrail-/` |
| 本地开发 Redirect URL | `http://localhost:5173/` |

如果本地实际使用 `127.0.0.1`，还需单独允许 `http://127.0.0.1:5173/`。生产地址必须保留仓库路径和末尾 `/`；更换域名时同时更新这里与部署配置。

分别测试注册验证邮件和密码重置邮件。Supabase 的默认邮件服务可能仅适合测试，并有收件人、速率等限制；正式开放前检查当前邮件设置，必要时配置自己的 SMTP 服务。不能只因调用返回成功，就认为邮件已经送达。

验证或重置链接应回到实际部署的网站。应用使用 PKCE 处理认证跳转；如跨浏览器打开邮件链接导致登录未完成，先确认邮箱验证结果，再回到原入口登录，不要反复创建账户。

## 4. 配置本地开发与 GitHub Pages

本地开发复制 `.env.example` 为被 Git 忽略的 `.env.local`，填写公开连接信息，再重新启动开发服务器。

```dotenv
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
```

GitHub Pages 的构建不能读取你电脑上的 `.env.local`。本项目的部署工作流已配置项目所有者提供的公开 Project URL 和 Publishable key，无需另外填写 GitHub Variables。若要改用其他项目，可在仓库的 **Settings → Secrets and variables → Actions → Variables** 中添加同名 Repository variables 覆盖这两项配置。更换 URL 时需要同时提供该项目的 Publishable key 或 anon public key，不会沿用本项目的默认 key。

工作流设置 `MONEYTRAIL_REQUIRE_CLOUD=1`：配置无效时拒绝发布账号版。这两个值是前端公开配置，不是管理凭据。构建通过仅验证配置格式与程序生成，不能证明数据库已初始化或真实账号隔离已经验证。

更新配置后需要重新构建和发布；修改 Dashboard 或 Repository variables 本身不会改写已经上线的 JavaScript。仓库子路径继续由 `MONEYTRAIL_BASE_PATH=/Moneytrail-/` 处理。

如果要从 Codex 云环境连接托管项目验证，还需要在环境网络设置中允许**实际项目的 HTTPS 主机名**。保留现有允许列表、代理和 CA 信任；不要关闭 TLS 校验或绕开代理。

## 5. 迁移现有本机账目

本机账目属于使用这台设备的人，不会因为登录一个账户就自动上传。迁移流程应明确展示目标账户，并由用户决定：

1. 先导出当前本机的 JSON 完整备份。
2. 登录准备接收账目的账户，确认当前邮箱。
3. 查看本机账目与云端账本，确认导入或合并内容。
4. 明确确认后上传，等待界面显示云端同步成功。
5. 验证另一台设备能够看到相同账目后，再决定是否移除旧的本机副本。

已有云端账本时，迁移保留现有记录，只跳过编号和全部字段一致的记录。相同编号但内容不同的旧记录使用独立编号，并修正退款关联；再次迁移可识别这些记录。金额、时间相近的记录仍需人工核对。原始备份应保留。清空账户账本、恢复备份等操作也会影响云端，确认文字会说明影响范围。

## 同步、离线与退出登录

缓存按 Supabase 项目和用户 ID 分开，不会把旧的 `moneytrail:v1` 本机账本当作任意账户的缓存。账户切换时需要清除上一账户的界面和临时状态。

离线或请求失败时，应区分“已保存在当前设备、等待同步”和“已同步至云端”。首次登录尚未取到账本时，不能把一次失败的请求当作空账本，从而覆盖云端内容。

多设备同时修改会触发版本冲突。界面应保留当前设备尚未同步的内容，提供备份，再由用户选择使用云端版本或明确覆盖；不采用静默的最后写入者覆盖。

退出登录前检查待同步修改。需要先同步或导出备份，再由用户确认退出；退出后清理该账户的本机账目缓存和页面状态。认证会话由 Supabase SDK 管理。

## 隐私边界

独立账户解决的是身份认证、跨设备恢复和用户之间的数据隔离。它不等于端到端加密，也不会自动把离线缓存或导出的 JSON/CSV 加密。

- 本机缓存仍可能是明文；保持登录的已解锁设备可以查看账本。
- 数据库管理员和具备管理权限的服务仍可能访问云端内容。
- `wenzo-zwz.github.io` 下的多个项目共享浏览器来源，项目路径不是浏览器存储的安全边界。正式使用时可考虑为账本配置独立域名。
- GitHub Pages 公开的是程序文件，真实账目发送到所配置的 Supabase 项目，不应写入源码、Actions 日志或部署产物。

## 发布前验证

验证分为两个层次，结果必须分别记录：

1. **本地数据库与客户端验证**：单元测试、PGlite 中实际执行迁移的权限和版本冲突测试，以及浏览器状态和缓存切换测试。PGlite 测试中的身份夹具用于模拟数据库的 JWT 上下文，不能证明托管认证服务已经接通。
2. **真实 Supabase 项目验证**：使用两个独立的测试账户，走完注册、邮箱确认、登录、重置密码、保存和换设备读取。

真实项目至少应确认：

- 账户 A 新建的账目，账户 B 查询不到。
- B 即使伪造 A 的用户 ID 或直接调用表接口，也不能读取、更新或删除 A 的账目。
- 未登录请求不能读取账本或调用保存函数。
- 两台设备基于旧版本同时保存时，后一次过期写入被拒绝，待同步内容仍可备份。
- 退出后登录另一个账户，页面和缓存不会显示上一账户的内容。
- 离线修改的提示准确，重新联网同步成功后另一设备能读取。
- 本机迁移只在明确确认后发生，迁移失败仍保留原始账目。

在托管项目未配置、邮件未验证或这些隔离检查未完成时，不应把账号版描述为已经可上线使用。
