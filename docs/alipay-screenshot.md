# 支付宝截图录入：轻点背面两下

网页已实现截图文字接收、候选识别及核对保存，**真实 iPhone 截图、OCR 和轻点背面仍待验收**。以下用于配置手机快捷指令和试用。正式共享 iCloud 安装链接尚未发布；可先手动搭建，完成后分享空白指令供维护者审核。

这条方案可在用户现有的 iOS 18.6.2 上准备，无需为了截图升级系统。由用户主动触发，不监听通知，也不自动提交消费；不需要短信接入令牌或外部模型。

## 搭建整条快捷指令

在 iPhone“快捷指令”App 新建指令，可命名为 **MoneyTrail 支付宝截图**。菜单名称以设备实际显示为准，依次添加：

1. **截屏**。截取当前显示的支付宝交易提醒或交易详情。
2. **从图像提取文本**。图像输入选择上一步的“截屏”结果，使用手机系统 OCR。
3. **URL 编码**。输入选择上一步提取的文本，操作选择编码。只编码 OCR 文字，不编码完整站点地址。
4. **文本**。先填入下面的固定地址，再紧接着插入上一步“URL 编码”的结果变量，放在同一行：

   ```text
   https://wenzo-zwz.github.io/Moneytrail-/#alipay-screenshot=
   ```

   实际内容应为“固定地址＋编码后的 OCR 变量”，不要把变量名、示例正文、加号或尖括号作为普通文字输入。
5. **打开 URL**。输入选择上一步“文本”的完整结果。不要直接打开未拼接地址的 OCR 文字。

截图和文字均应使用上一步的真实输出变量，不能写死某条消费。可以先手动运行整条指令检查变量和授权；网页更新完成后再验证完整交接与保存。

## 将轻点背面两下绑定到整条指令

按 [Apple 的轻点背面说明](https://support.apple.com/zh-cn/111772)，进入：

**设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下 → 选择“MoneyTrail 支付宝截图”**。

选刚搭好的整条快捷指令，不能只选系统的“截屏”动作，否则只会截图，后面的 OCR 和打开网页不会执行。先按设备提示完成所需授权，再打开要记录的支付宝页面，轻点背面两下。手机是否支持及触发效果以实际设备为准。

## 网页核对流程

1. 网页收到文字后进入“录入 → 支付宝截图”；也可在该标签页手动粘贴手机 OCR 文字。
2. 快捷指令传入后自动生成候选；手动粘贴文字时点击识别。OCR 可能混入其他通知、按钮和金额，逐笔核对，不把识别成功视为已经入账。
3. 打开候选编辑，确认商户、金额、分类、交易类型和交易发生时间。未识别到时间时保持空白，需本人补全；截图时间、当前时间及通知的相对时间不能直接代填。
4. 确认保存后才生成来源为支付宝的账目。与已有银行短信或 CSV 账单疑似重复时，先核对原记录；程序只提示，不自动合并或删除。

截图图片不上传站点。OCR 文字通过 URL 的 `#alipay-screenshot=` 片段交接，站点启动时清除合法的截图专用片段；需要登录时，文字仅在当前页面内存暂存，登录后继续。刷新、关闭页面或换浏览器可能丢失未保存文字，可重新主动截图。不要分享含识别文字的临时链接；确认保存的账目按本机／账户模式正常保存或同步。

## 当前识别范围

已知交易提醒格式如下（示例商户）：

> 你在滴滴出行有一笔38.40元的免密/自动扣款支付，点此查看详情。
>
> 你在上海示例信息科技有限公司有一笔140.50元的免密/自动扣款支付，点此查看详情。

本轮仅处理这类明确支付格式及有限的显式交易字段，不承诺任意支付宝付款截图均可识别。真实交易详情页样本尚未取得；金额或商户不明确时，改为人工录入，不根据页面中任意数字猜消费。

无金额银行卡支出概览、积分出行、芝麻粒、公益、收益、优惠消息不应生成消费候选；退款、失败、转账等不能按普通消费格式处理。滴滴可归交通／打车，未知公司保留商户原名并待分类。
