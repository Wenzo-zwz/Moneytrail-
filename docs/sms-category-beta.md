# MoneyTrail 短信分类测试版

这条测试指令使用独立的「信息」自动化。启用「在 iPhone 确认」后，符合格式的工行支出先进入「待确认」，再由 iOS 显示分类列表。确认分类后才会入账。为具体商户开启直接入账后，符合该规则的支出会自动记录，并显示金额和分类。

## 在 MoneyTrail 上配置

打开「短信自动记账 → 接收与记录 → 收到短信后」，选择「在 iPhone 确认」，再选择确认深度并保存。

- 「只确认一级」默认开启。选完一级分类就提交入账。
- 「也确认二级」会接着显示该类的二级选项。选一个二级，或点「只记一级」后提交。需要填写自定义二级时，可以点「稍后处理」，回到收件箱核对。

已保存的「个人商户分类规则」可在列表里作为推荐。想让某家商户免确认时，在「分类与历史整理 → 个人商户分类规则」编辑该规则，开启「iPhone 确认时，这家直接入账」。

## 在 iPhone 上配置

1. 将签名后的 `MoneyTrail-SMS-Category-Beta.shortcut` 保存到「文件」，点开并添加快捷指令。安装时填入现有记账指令使用的个人短信接入令牌，可在原指令第一条「文本」动作里查看。继续沿用这个令牌，避免旧指令因令牌更换而失效。
2. 在 Beta 指令里添加「信息」触发卡，选一个现有记账自动化未覆盖的发件人，启用自动化并关闭运行前确认。也可以在「快捷指令 → 自动化」新建「信息」自动化，设为「立即运行」，把收到的信息正文传给测试指令。每个发件人配置一个触发入口。
3. 第一次收到测试短信时保持解锁，完成 iPhone 对网络请求的授权。用另一条信息验证允许授权后的自动运行。

若工行发件人已经由正式自动化处理，可让一个正式自动化未覆盖的可信联系人发送下面这条模拟信息。把月日、时间改成发出时的时间。重复发完全相同的正文会被去重，每次测试请改一下测试金额。

```text
尾号1234卡11月22日12:30支出(消费财付通-测试咖啡店)1.23元，余额123.45元。【工商银行】
```

同一条真实短信交给两条自动化会产生竞争，谁先接收就按谁的规则处理。测试时让正式自动化和测试版使用互不重叠的发件人。

## iPhone 验收

| 情况 | 观察结果 |
| --- | --- |
| iPhone 解锁，正在用其他 App 时收到信息 | 分类列表有没有直接浮在当前页面上，是否需要先点通知 |
| 「只确认一级」模式下选一级 | 看到成功提示，账本只多一笔，金额和一级分类正确 |
| 「也确认二级」模式下选一级 | 接着显示该类的二级列表。选二级或「只记一级」后，核对实际记录的分类 |
| 在任一列表点「稍后处理」或关掉列表 | 短信在「短信自动记账 → 待确认」，账本没有新增支出 |
| 已保存商户规则 | 核对弹窗里的推荐。开启该商户的直接入账后再用新的短信测试，核对只新增一笔且通知显示正确的金额和分类 |
| 锁屏时收到一条不同的短信 | 记录锁屏提示及解锁后的行为。只要服务器已经接收，未选分类的短信应在待确认 |

本轮用识别明确的工行支出做原生弹窗实验。类型或金额尚需核对的短信继续在收件箱处理。

## 使用 Mac 签名

在本项目目录运行 Apple 自带的签名命令，再把输出文件传到 iPhone。

```sh
plutil -convert binary1 -o MoneyTrail-SMS-Category-Beta.unsigned.shortcut public/shortcuts/moneytrail-bank-sms-category-beta.unsigned.plist
shortcuts sign --mode anyone --input MoneyTrail-SMS-Category-Beta.unsigned.shortcut --output MoneyTrail-SMS-Category-Beta.shortcut
```

分发的源文件使用空白令牌。安装后再输入个人令牌。
