# 日常短信自动分类与批量整理

用户已确认：修复嵌套括号，按渠道后的商户和用途自动分类；已有待确认和待分类可批量处理；群收款及用途不明的个人转账继续确认。

- 工行短信先完整验证格式，再解析配对括号中的描述；独立读取交易金额，余额不参与金额计算。保留币种、安全短信、日期、多事件和查重保护。
- 滴滴归交通，美团无更明确业务时默认餐饮，烟酒副食归购物。明确买药、酒店、打车等用途优先于平台默认类别。补全餐饮、购物、交通、居住、医疗、娱乐、学习的日常规则。
- 财付通、微信、支付宝是渠道；具体商户明确时正常判断，只有渠道、群收款及不明个人转账保持待确认。明确的微信零钱充值、本人账户互转、信用卡还款等资金周转可记录为 transfer，不计消费。话费充值等实际消费不能误当资金周转。
- 具体商户分类规则按账户隔离，由用户主动保存或删除；通用渠道和群收款不能记成永久分类，规则不能绕过格式、重复和转账复核。
- 待确认先展示可自动入账的明细、依据和剩余笔数，再显式批量应用。应用仅处理预览的记录，重算结果变化时拒绝过期预览；不处理新到短信，不重复添加流水。
- 已入账账目只整理 expense 且 category=待分类 的记录，先预览再更新原记录；保留已有分类、金额、日期、预算及退款关联。分类更改使相关月份需要重新核对。支持撤销本次分类；被后续编辑的记录不允许旧撤销覆盖。
- 云端分类、短信接入、重新识别使用相同规则；TS 客户端用于分类预览和本机手动短信，数据库负责无人值守自动入账。
- 不自动执行真实账本批量处理，不接触用户令牌；新增 SQL 由项目所有者应用到 Supabase，生产发布另行确认。
