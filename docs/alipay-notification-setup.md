# 支付宝通知适配：先核对系统能力

当前实机反馈：用户在个人自动化触发条件列表搜索“通知”没有结果，系统版本待核对。此前“已确认支持通知触发”的判断已撤回；能在“App”触发中选择支付宝，或建立接收输入的快捷指令，都不能证明支持收到支付宝通知时自动运行。当前暂停通知自动化取样，不继续配置上传。

正式通知接收入口与可安装的支付宝模板尚未交付；银行卡短信入口不能接收支付宝通知。本文后面的通知取样步骤只适用于已确认存在对应触发器的设备，不向账本提交数据。

## 先确认可用路线

1. 在“设置 → 通用 → 关于本机”查看实际 iOS 版本，再核对设备上是否有“收到通知”触发。[Apple 的 iOS 27 更新说明](https://support.apple.com/en-us/149045)将 Notifications 列为新增自动化，不能直接套用到旧版本手机。
2. 没有通知触发时，不用“App 打开”或“交易”来冒充通知来源，也不假设快捷指令可以后台读取通知中心。
3. 目前已交付的替代路径是银行短信接入和支付宝 CSV 账单导入。截图分享、从图片提取文字后生成候选可作为后续手动触发方案，但当前产品尚未交付此入口，不能标作已支持。
4. 若采用截图来源，应明确标识截图／手动输入，不将其称为已采集的系统通知；仍需核对完整正文、日期及重复记录。

## 确认有通知触发后：建立临时取样自动化

1. 在 iPhone 的快捷指令中建立一条临时通知自动化，应用选择“支付宝”。名称可用“MoneyTrail 支付宝通知测试”。具体入口以当前系统版本显示为准。
2. 取样阶段先只限定应用，暂不添加标题或正文关键词，以便确认系统实际传出的输入。取样完成后再设置交易通知筛选。
3. 添加一个“快速查看”操作，输入明确选择“快捷指令输入”。不要填固定的通知正文，也不要调用现有银行卡接收地址。
4. 先在手机解锁时，等待下一条正常收到的支付宝通知，查看快捷指令实际显示的内容。无需为了测试额外消费。
5. 记录取样内容是否包含标题、完整正文、金额、商户，以及系统版本。反馈时可以复制显示的文字或提供截图，隐去私人信息，不包含个人令牌。

若显示为空、只显示图标或标题，先检查输入参数及当前通知可用的属性，再决定提取方式；不能据截图中的通知正文推定自动化一定取得同样内容。历史通知不作为新通知触发的证明。取样结束后停用临时自动化，避免后续所有支付宝消息继续弹出快速查看。

## 第二步：依据实际输入制作正式模板

正式模板应完成“通知触发 → 提取确认过的标题／正文 → 交易筛选 → 通知专用接收入口 → 展示真实返回状态”。模板使用安装者自己的接入能力，不嵌入作者的个人令牌；分享副本与个人使用副本分开。不得把支付宝通知改写成银行卡短信或添加银行签名。

截图中可识别的格式为：

> 交易提醒
> 你在〔商户〕有一笔〔金额〕元的免密/自动扣款支付，点此查看详情。

最初仅将符合此格式的人民币正金额支出作为候选，全部待确认。滴滴出行可复用交通／打车分类；未知公司保留原名并待分类。无金额银行卡概览、出行、芝麻粒、公益和收益消息不生成账目。退款、失败、转账等其他格式需要单独样本和规则，不能套用本格式。

## 接收与入账前的必要条件

- 正文未提供交易时间；接收时间只能标注为接收时间，不能冒充交易发生时间。
- 正文没有订单号；通知事件编号不能冒充支付宝交易编号。
- 同一商户同价的两次消费可能正文相同，不能按正文做一天内硬去重。同一次提交重试应复用事件编号。
- 与银行卡短信或支付宝账单疑似同一笔时先提示核对，不能仅按金额自动删除或合并。
- 解锁取样通过后，还要在真实锁屏、正常联网及支付宝前后台情况下核对触发。网页端的解析测试不能代替这些手机验证。
- 正式接收端、收件箱、确认与忽略、备份及旧客户端兼容完成并验收后，才发布正式安装入口。
