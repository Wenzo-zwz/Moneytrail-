# 支付宝录入：通知与主动截图两条路线

当前用户设备为 **iOS 18.6.2**，在个人自动化触发条件中搜索“通知”没有结果。此前“已确认支持通知触发”的判断已撤回；能在“App”触发中选择支付宝，或创建接收输入的快捷指令，不能证明收到支付宝通知时可以自动运行。

本轮改为实现用户选择的**轻点背面两下 → 截图 → 手机 OCR → Moneytrail 核对保存**。这是用户主动发起的截图录入，不是监听通知。网页已实现文字接收和候选核对；真实截图、OCR 和轻点背面触发仍待验收。

| 路线 | 当前状态 | 用户下一步 |
| --- | --- | --- |
| iOS 18.6.2 后台通知自动化 | 本次设备没有对应通知触发入口；正式通知接收端和模板未交付 | 暂停取样和上传，不再搜索该入口 |
| 支付宝主动截图 | 网页端已实现；不需要升级系统、短信令牌或外部模型 | 按[截图录入说明](alipay-screenshot.md)准备整条快捷指令，按发布后的网页验证 |
| 支付宝 CSV 账单 | 已有导入流程 | 可继续通过账单补全和对账 |

## 当前选择：主动截图并确认保存

打开支付宝交易提醒或详情，由用户轻点背面两下运行整条快捷指令：截屏、从图像提取文本、编码文字、打开 Moneytrail。站点收到文字后显示“支付宝截图”候选；本人核对商户、金额、日期和类型后才保存。没有交易时间时留空补填，不以截图时间或当前时间代替。

不需要图片上传或短信接入令牌。截图在手机上由系统 OCR 提取文字；URL 片段只用于交接识别文字，网页启动后清除合法的截图专用片段，登录前仅在当前页面内存暂存。确认保存后的账目按本机／账户模式正常保存或同步。完整搭建步骤和验收边界见[支付宝截图录入](alipay-screenshot.md)。

## 将来如需后台通知：重新核对实际系统能力

[Apple 的 iOS 27 更新说明](https://support.apple.com/en-us/149045)列出了 Notifications 自动化能力，不能套用到旧版本手机。本次截图方案不要求升级；升级也不等于全部支付宝通知都能取得完整正文或自动入账。

只有设备确实提供对应通知触发器，才考虑以下取样；目前无需在用户的 iOS 18.6.2 上操作：

1. 临时通知自动化选择支付宝，仅用“快速查看”显示实际“快捷指令输入”，不调用任何入账接口。
2. 等待一条正常的新通知，记录是否取得标题、完整正文、金额和商户，以及设备／系统版本。无需额外消费。
3. 解锁取样通过后，再核对锁屏、联网、支付宝前后台等情况；结束后停用临时取样。

“打开 App”或“交易”触发不能冒充支付宝通知来源，也不能据截图推断自动化输入。正式通知路线还需独立接收协议、来源与凭据、确认／忽略、事件幂等及账户隔离验证；银行卡短信入口不接受支付宝通知，不能改写正文或补造银行签名绕过检查。

## 两条路线共用的账目边界

- 目前已知样本是“你在〔商户〕有一笔〔金额〕元的免密/自动扣款支付，点此查看详情。”。截图解析仅适配明确格式及有限的显式交易字段；尚未取得真实详情页样本，不承诺任意付款截图可识别。
- 滴滴出行可按交通／打车分类；未知公司保留原名、待分类。无金额银行卡概览、积分出行、芝麻粒、公益、收益等消息不生成消费记录。
- 截图或通知未提供交易时间时，不把接收时间或截图时间当成交易发生时间。没有订单号时，也不编造支付宝交易编号。
- 同商户同价两次消费可能正文一致，不能按正文做全天硬去重。与银行卡短信、CSV 账单相近的记录仅提示核对，不自动删除或合并。
