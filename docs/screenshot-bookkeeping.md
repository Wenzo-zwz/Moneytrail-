# 截图记账：支付宝、微信与其他支付页面

同一条 **MoneyTrail截图记账** 快捷指令用于支付宝、微信及其他支付页面：由用户轻点背面两下，依次截屏、用手机 OCR 提取文字、打开 Moneytrail，核对候选后确认保存。它不监听通知，不直接上传图片，也不在识别后自动记账。

通用截图入口与来源核对已实现。已有支付宝提醒格式继续保留，支持已核对的支付宝 OCR、明确字段的微信及通用支出文字，并可保留可靠的负数金额供补全核对。实际微信和其他支付截图样本仍待提供，完整真机识别与保存还需验收。通用的是操作流程，不代表任意版式都能识别。

截图流程不需要短信接入令牌或外部模型。2026-11-16 已在用户的 iOS 27.2.1 上确认背面触发、快捷指令打开网页、完整 OCR 文字交接及支付宝候选可用；完整保存和账户同步仍需按下方清单核对。共享模板已完成静态审核，可在快速上手中[安装 MoneyTrail截图记账](https://www.icloud.com/shortcuts/aea10170903740c4b268f105169711cf)，无需手动搭建五个操作；审核记录见[模板审核](screenshot-shortcut-audit-2026-11-16.md)。

## 快速上手入口

进入 **设置 → 快速上手 → 截图记账 → 设置截图记账**，在同一份指引中完成：

1. 在官网点「安装截图记账快捷指令」，打开 iCloud 后添加「MoneyTrail截图记账」。自定义部署可展开「配置 iPhone 截图快捷指令」，使用该站点的地址。
2. 绑定轻点背面两下，按手机提示授权。
3. 用一笔已有付款详情试记，查看上方候选卡、核对支付来源与日期，确认保存后到账目页检查。

整段 OCR 原文保留在“查看或编辑识别文字”中，原文不变不代表识别失败；提取结果显示在上方候选卡。快速上手的“打开截图识别”会进入录入页，已有截图草稿会保留。

模板只负责截屏、手机 OCR、编码和打开网页。识别规则由网页统一维护，用户配置同一条指令后即可使用更新后的识别能力。共享配置登记在 `public/shortcuts/screenshot-profile.json`，包含名称、版本、实际 iCloud 分享链接和固定目标地址；未登记有效链接或当前站点地址不一致时，不提供该模板的安装入口。自定义部署请使用自己的地址手动配置，避免把截图送往其他站点。

## 自定义部署的快捷指令

在 iPhone“快捷指令”App 新建 **MoneyTrail截图记账**，按设备实际显示的菜单依次添加：

1. **截屏**。截取当前显示的一笔支付详情或完整交易提醒。
2. **从图像提取文本**。图像输入选择上一步“截屏”的结果，使用手机系统 OCR。
3. **URL 编码**。输入选择上一步的识别文字，操作选择编码。只编码 OCR 文字，不编码完整站点地址。
4. **文本**。填入固定地址，再紧接着插入上一步“URL 编码”的结果变量，放在同一行：

   ```text
   https://wenzo-zwz.github.io/Moneytrail-/#screenshot=
   ```

   内容是“固定地址＋编码结果变量”。不要把变量名称、示例正文、加号或尖括号当作普通文字输入。
5. **打开 URL**。输入选择上一步“文本”的完整结果。

各动作都使用前一步的真实输出，不能写死某条消费。支付宝、微信和其他支付页面共用这条指令，不用按平台分别创建。先手动运行检查变量和授权，网页更新后核对完整交接与保存。

## 绑定轻点背面两下

按 [Apple 的轻点背面说明](https://support.apple.com/zh-cn/111772)进入：

**设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下 → 选择“MoneyTrail截图记账”**。

选择整条快捷指令，不能只选系统“截屏”动作，否则后续 OCR 和打开网页不会执行。按设备提示完成权限授权，再回到付款页面轻点背面两下。设备支持情况及触发效果以真机为准。

## 网页核对与保存

1. 网页接收文字后进入录入页的“截图记账”，默认显示候选账目；原始 OCR 折叠在“查看或编辑识别文字”中。也可通过“粘贴付款详情文字”手动输入；识别失败时点“检查识别文字”查看或修正原文。
2. 逐笔核对商户、人民币金额、交易类型、来源及日期。OCR 可能混入其他通知、按钮和金额，识别成功不等于已经入账。金额和付款证据明确、商户或时间缺失时仍保留候选；“商户待填写”和缺失时间必须在核对表单中补全后才能保存。
3. 来源只有明确显示支付宝或微信时才自动标识对应平台；用户可纠正。无法确认时保留“其他／未确认”，按手动录入保存，不默认猜为支付宝。
4. 未识别到交易发生时间时保持空白，由本人补全；当前时间、截图时间和通知相对时间不能直接代替。
5. 确认保存后才新增账目。与银行短信、支付宝或微信 CSV 账单相近的记录仅提示核对，不自动合并或删除；同商户同价两次真实消费也不能直接当成重复。
6. 只识别到唯一负数金额、没有明确付款证据时显示金额提示；本人确认这是一笔支出后，可点“确认是支出并补全”，在表单补齐商户和实际交易时间。余额、退款、转账、外币及多个金额含义不清的输入不能走这个入口。

图片留在手机上进行 OCR。识别文字通过 `#screenshot=` URL 片段交接，网页启动时清除合法的截图专用片段；需要登录时仅在当前页面内存暂存，登录后继续。刷新、关闭页面或切换浏览器可能丢失未保存文字，可重新主动截图。不要分享含识别文字的临时链接；确认保存后的账目按本机／账户模式正常保存或同步。

## 识别边界与旧指令兼容

- 保留原支付宝明确提醒格式，例如“你在〔商户〕有一笔〔金额〕元的免密/自动扣款支付，点此查看详情。”。
- 苹果 OCR 输出之后，网页会规范金额格式，提取唯一明确的负数金额，再结合付款成功或“交易成功＋付款字段”生成待核对支出。页面标题、积分、收单机构等辅助文字的缺失或换序，不会单独阻断清楚的金额。商户和时间分别按证据填写，无法确定就留空；不能从商品、订单号、手机时钟或账户余额猜出交易字段。未显示币种时会提示核对人民币候选；没有明确平台名称时仍需本人选择支付来源。
- 微信和其他支付页面仅在显式交易字段足以确定一笔清楚的支出时生成候选；实际样本仍待核对，不承诺所有支付详情或付款成功页面都支持。
- 收款、退款、转账、处理中、失败或多金额含义不明的内容不能按普通支出记录，改为人工核对；不从任意数字猜消费。
- 无金额银行卡概览、积分出行、芝麻粒、公益、收益及优惠消息不生成消费候选。未知公司保留商户原名并待分类。

原 **MoneyTrail 支付宝截图** 指令及 `#alipay-screenshot=` 地址保留兼容；旧地址只是输入入口，不再强制把文字来源设为支付宝。可将旧指令改名为 **MoneyTrail截图记账**，将文本动作前缀改为上面的 `#screenshot=`，其他动作仍保持同一流程，并重新确认轻点背面的绑定。
