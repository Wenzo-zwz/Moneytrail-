## 规则如何更新

`shortcuts/bank-rules.json` 是编辑源。构建生成 `public/shortcuts/bank-rules.json` 和内容完全相同的 `bank-rules.txt`。TXT 供 iPhone 保留原始清单文本，网页读取 JSON 查看发布版本。规则文件包含固定六字段，按规定顺序输出。发布校验检查格式、大小、版本及五行收支和隐私样例。它无法判断某台手机当前使用的规则。

维护者修改规则后增加 `version`，更新 `publishedAt`，运行：

```sh
python scripts/build-bank-shortcut.py
node scripts/check-bank-shortcut.cjs
```

只有新版本通过发布检查，才应上传到生产站点。构建以已生成的清单作版本基线，同版本内容变更或降级会失败。发布回滚也要使用更高版本，审阅时和上一份上线版本比对。

1. 更新指令从固定的公开地址获取清单，校验格式、项目、最低指令版本以及手机上的消费和验证码样例。只有版本严格更高时，才把完整清单保存为 `bank-rules-v4.txt`。同版本安静结束。
2. 短信指令对收到的正文先做固定的长度、验证码、控制字符和银行来源检查，再选用本机缓存规则。缓存缺失或结构预检失败时用内置规则。站点只提供匹配数据，短信发送地址、令牌、正文输入和本机拦截保持由指令控制。
3. 规则更新用单独的定时自动化。测试中断网触发系统请求超时，更新没有到达保存动作，旧规则仍可离线使用。单独的短信提交需要网络，离线重试队列仍待实现。

新增银行或触发方式可能需要服务端适配和调整发件人。已有自动化若还限制正文包含「支出」，只触发符合这个条件的短信。iOS 行为或指令结构变更需要更新指令本体。

## 通用签名与首次安装

这两个公开源使用 Apple 文件动作，目录待安装者选择。短信指令的令牌与导入问题默认值为空：

- `public/shortcuts/moneytrail-bank-v4.unsigned.plist` 对应「MoneyTrail 银行收支记账 v4」。
- `public/shortcuts/moneytrail-rule-update-v4.unsigned.plist` 对应「MoneyTrail 更新银行规则 v4」。

用个人 Mac 执行 `shortcuts sign --mode anyone --input <未签文件> --output <签名文件>`。导入两份签名文件，从快捷指令复制各自的 iCloud 分享链接。分享用副本保留空白令牌和未选择目录的状态。私有试用文件包含已选的本机目录，通用分发使用上面的公开源。

用真实分享链接运行审核：

```sh
python scripts/audit-bank-shortcut-v4.py <短信指令的iCloud链接> <更新指令的iCloud链接>
```

审核下载 Apple 的原始与已签资产，检查签名状态、动作与引用、固定地址、空令牌和目录绑定。Apple 导出的动作存在差异时，核对差异后处理。签名和动作审核之后，请另一位试用者在 iPhone 完成一次首次配置：

1. 安装两条指令。短信版填自己的接入令牌。
2. 在「文件 → 我的 iPhone」建 `MoneyTrail` 文件夹。更新指令的读取、保存和短信指令的读取都选这个文件夹，文件名保留 `bank-rules-v4.txt`。
3. 解锁运行更新指令，完成网站与目录授权，检查写入的规则。设单独的「特定时间」自动化，每天运行更新指令，关闭运行前确认。
4. 新建银行短信触发，实际发件人按收到的短信选择，「信息包含」留空，把短信正文传给短信指令。若已有同一发件人的自动化，可修改原来的运行目标。锁屏收到下一条正常交易短信后，在收件箱查看对应记录。

两条链接审核且首次安装通过后，在 `public/shortcuts/bank-rules-v4-profile.json` 填入 `smsUrl` 和 `updateUrl`，将 `releaseVerified` 设为 `true` 后部署网页。入口要求两条链接都有效且不同，并且属于官方项目。网页不会通过规则下载自动替换用户手机中的旧指令。

## 已知边界

下载超时由系统处理。当前没有通用异常捕获、固定两秒超时、原子比较并覆盖或离线短信补传。缓存结构预检可以拒绝截断及不兼容的清单，任意文件授权、编码、非法正则或并发覆盖故障仍可能中断运行。手机固定保护只覆盖已检查的来源与字符形式。发布校验和单机实测不能替代另一台设备的首次安装验证。
