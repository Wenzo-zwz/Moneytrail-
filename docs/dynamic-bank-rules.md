## 已交付

- `shortcuts/bank-rules.json` 是唯一编辑源；`public/shortcuts/bank-rules.json` 由构建器生成。
- `public/shortcuts/bank-rules.txt` 从同一编辑源生成，与公开 JSON 字节一致，供手机验证纯文本下载。它不是第二份规则源，也不是可安装指令。原生“获取 URL 内容”可能自动将 JSON 转成词典；目前没有证据表明词典再转文字会保留原始顺序和格式，不能依赖这种转换验证缓存。纯文本返回类型仍需在真机上确认。
- 首版 `schemaVersion: 1`、`version: 1`、`minShortcutVersion: 4`；匹配规则来自冻结的五行收支 v3。最低指令版本声明面向后续设计，不代表 v4 已存在可安装产物。
- 仅允许格式版本、规则版本、最低指令版本、固定生产项目、UTC 发布时间和匹配规则六个字段。不提供请求地址覆盖、个人令牌或可执行动作。
- 网页通过公开 GET 查看已发布版本，可复制规则供制作和人工核验；它不能读取手机文件，也不能据此判断手机是否安装、已更新或成功转发。
- 自定义项目不读取这份生产规则，也不显示其地址或复制入口。规则读取失败不改变现有模板、短信接收或收件箱。

维护者修改编辑源后，增加 `version` 并更新 `publishedAt`，运行：

```sh
python scripts/build-bank-shortcut.py
node scripts/check-bank-shortcut.cjs
```

构建使用项目要求的 Node 24 和同一份浏览器校验函数，不增加依赖。默认以工作树中现有公开文件作为上一版比较，拒绝相对它的降级或同版本内容变化；回滚也应发布更高版本。此比较不是 Git 历史防篡改：同时手动修改编辑源与公开文件会绕过该基线，审阅者仍需核对已发布历史版本。`--check` 核对公开文件与编辑源一致，不修改文件。

网页仅检查精确字段、项目、整数版本、时间、大小限制和 JavaScript Unicode 正则编译，不用远程正则执行文本匹配。五行收支、验证码、Cf、混合银行和长度等固定正反例只在发布校验子进程执行，最多运行 15 秒；此限时不适用于手机快捷指令。**格式检查和固定回归例子不能证明任意正则安全，也不能证明 Apple ICU、文件访问或短信自动化运行成功。** 每次变更仍需审阅；不要发布未经核对的规则。

## 拟定的最小手机结构

初次安装新结构需要更新一次。后续银行规则变化由独立的“更新银行规则”指令下载，短信执行不承担刷新。

1. 短信指令先执行独立、固定的本地 OTP、长度、控制字符和来源保护，再使用最后成功缓存或内置规则；远程规则不能绕开保护或改动接收地址、令牌和输入。
2. 更新指令向固定地址下载清单，校验格式、项目、版本和 `minShortcutVersion`，在本机验证正则与固定案例；全部成功后才替换缓存。版本不兼容时保留旧缓存并提示升级。日常规则更新不需要重装，新增动作结构仍需要更新指令本体。
3. 短信指令不调用更新指令。这样下载失败只影响更新；既有提交请求自身的网络故障仍可能阻止接收，不能承诺离线提交成功。
4. 本机状态展示实际内置／缓存来源、版本和更新时间；网页仅能展示最近一次成功接收上报的版本，两者不混用。

远程清单只处理匹配数据。新增银行仍需服务端接收和解析适配、手机选择实际发件人；iOS 触发机制和执行动作的变化也不能靠 JSON 远程修复。当前网页没有接入手机规则版本上报，不展示虚构的手机版本。

不能依赖原生“获取 URL 内容”后面的“如果”捕获 DNS、TLS 或超时错误。现有已审产物没有可保证的通用 try/catch 或 2 秒超时设置。苹果的 [API 指引](https://support.apple.com/en-mt/guide/shortcuts/apd58d46713f/ios)描述请求方法和请求体，没有提供这些保证。

只改测试副本，不删除已保存文件，不修改正式短信自动化：

1. 复制“MoneyTrail 读取缓存”为“MoneyTrail 缓存缺失测试”。关闭读取动作的“未找到时报错”，路径暂改为 `definitely-missing.txt`。
2. 在文件读取后添加“如果”，输入明确选择该读取动作的“文件”，条件为“有任何值”。
3. 把原有“从文件获取文本”及显示该文本的通知放在“如果”分支内；“否则”中添加固定通知。最新样本的实际通知文案为 `已使用内测测试规则`。
4. 运行后应显示这句固定通知且没有文件错误。这是分支验证，**仅仅没有红色错误不算分支通过**。
5. 将路径恢复为 `cache-test.txt`，再次运行应显示 `MoneyTrail-cache-test`，验证有文件分支。用户已明确确认两种文件名的运行结果均符合预期；共享导出保留缺失路径，方便重复验证。

此处只验证“文件不存在时返回空结果并进入否则分支”，固定通知没有执行真实内置匹配规则。**正式内置规则回退、锁屏运行和远程规则更新仍未完成验证。**

“从文件获取文本”不能放在判断之前，也不能依赖隐式的上一项输入；否则空文件结果可能被错误地替换为其他动作输出。
